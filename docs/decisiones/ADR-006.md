# ADR-006 — Aseguramiento de calidad y CI manual

**Estado:** Acordado en planificación; implementación del workflow pendiente de validación en GitHub.

## Contexto

NeuroVision se desarrolla en tres semanas por cuatro estudiantes, con cinco capas y contratos compartidos. Se revisaron las buenas prácticas del repositorio académico Posgrados, incluyendo pre-commit, script local, tests de arquitectura y pipelines de calidad.

## Decisión

Usar Ruff, mypy, Import Linter, pytest, ESLint, Prettier, TypeScript, Vitest, pre-commit y GitHub Actions. Los comprobadores deben usar un script local común. **El workflow oficial será exclusivamente manual con `workflow_dispatch`**, autorizado y supervisado por Jherson.

Cada ejecución declara número de PR, SHA revisado y suite seleccionada. Solo una ejecución completa validada, con revisión documentada y candidato sin cambios, podrá servir para aprobar integración. Conservar commits individuales mediante merge commits.

## Limitaciones y tareas

Un workflow manual lanzado desde `develop` no implica que GitHub aplique automáticamente required status checks al HEAD del PR. La protección de ramas y la política de autorización deben verificarse en el repositorio final. El archivo de configuración preparado no sustituye esa comprobación.
